GitHub Pages + Hexo 博客部署全教程

一、你是否有过这样的疑问

写了很多技术笔记、项目总结、学习心得，但都散落在本地硬盘和各个云笔记里，想发出去却不知道发哪。

想拥有自己的博客主页，一问才发现：

  • 买服务器：一年几百上千，还得自己装环境、维护系统；
  • 云主机备案：流程长、周期久，个人折腾起来心累；
  • 第三方平台：要么有广告，要么不自由，页面风格千篇一律。

于是疑问来了：有没有一种方案，不用花钱、不用维护服务器、还能完全自定义，把 Markdown 文章一键变成在线博客？

答案是：有。GitHub Pages + Hexo，就是目前个人博客圈子里最主流的免费方案。

二、GitHub Pages 到底能干什么

GitHub Pages 是 GitHub 提供的免费静态网页托管服务。

它的核心特点：

特点 说明
完全免费 个人用户无限个 Pages 站点，不花一分钱
无需服务器 静态文件托管，不用自己买主机、配环境
自动 HTTPS 默认带 https:// 安全访问，无需额外配置
代码驱动 代码推到仓库，页面自动发布上线
支持自定义域名 可绑定自己的域名，实现 blog.yourname.com
版本可控 内容全部在 Git 仓库里，改版、回滚都方便

那 Hexo 又是什么？

问题 2：打开网址 404

原因：仓库名不是 用户名.github.io 格式。GitHub Pages 只对同名仓库自动生效。

解决：要么把仓库改名为 你的用户名.github.io，要么部署到独立仓库的 gh-pages 分支（适用于项目文档站）。个人博客强烈建议直接用同名仓库。

问题 3：remote: Permission to ... denied

报错示例：

原因：git 推送认证失败。常见于用 HTTPS 推送但没有配置凭证。

解决（推荐 PAT）：

  1. GitHub → Settings → Developer settings → Personal access tokens → Tokens (classic)；
  2. 勾选 repo 权限，生成 token；
  3. 把 _config.yml 里的 repo 改为带 token 的地址（注意不要提交到公开仓库）：

问题 4：样式丢失、图片全 404

现象：本地预览一切正常，部署后 CSS 加载不出来、图片裂开。

原因：_config.yml 里的 url 没改，Hexo 生成了错误的绝对路径。

解决：把 url 改成你的真实地址：

改完重新 hexo clean && hexo generate && hexo deploy。注意：hexo clean 在改路径后必须执行，否则缓存里还是旧路径。

问题 5：部署成功但线上还是旧内容

原因：GitHub Pages 构建和 CDN 缓存有延迟，通常要等 1-3 分钟；另外浏览器本地缓存也会让你以为没更新。

解决：强制刷新（Ctrl + Shift + R），耐心等几分钟再访问。

问题 6：写了文章但首页不显示

原因：frontmatter 里的 date 是未来时间，Hexo 默认不渲染未来文章；也可能是 source/_posts 外的手动文件没有 frontmatter。

问题 7：Node 版本与 Hexo 版本不兼容

现象：hexo generate 报各种模块错误、语法错误。

解决：不要用最新的非 LTS Node 大版本。建议 Node 18/20 LTS + 当前 Hexo 稳定版；升级项目时先 npm update 再看报错。报错信息用 hexo generate --debug 能看到完整堆栈。

问题 8：分支混乱（main / master / gh-pages）

现象：推上去的页面找不到，仓库里多了好几个分支。

原因：GitHub 把默认分支从 master 改成 main 后，很多旧教程还写着旧分支名；同时 hexo-deployer-git 默认分支是 master。

五、总结

回顾整条链路，GitHub Pages + Hexo 的核心价值就一句话：

写 Markdown → 生成静态页 → 推送到 GitHub → 免费上线。

  • 费用：0 元（GitHub 免费额度完全够用）；
  • 维护：无服务器、无数据库、无备案，内容就是 Git 仓库里的 Markdown；
  • 扩展：主题、评论（giscus / Waline）、统计（不蒜子）、自定义域名，全部可自由配置；
  • 掌控：数据在自己仓库里，换平台随时迁移，不被任何平台绑架。

如果你已经在本地写了很多笔记，强烈建议今天就把博客跑起来。第一篇文章永远是门槛最高的，跑通一次，后面每次发文章只要三分钟。
