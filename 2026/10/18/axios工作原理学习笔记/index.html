axios 工作原理学习笔记

一、核心概念（一句话总结）

axios 是一个基于 Promise 的 HTTP 客户端，核心架构是一条固定管线：请求拦截器(加工) → adapter(发送) → 响应拦截器(收尾)；其中 adapter 是”发送器”且可插拔替换——本项目正是把默认的网络发送器换成 mockAdapter，才实现了”请求不出浏览器”的 Mock。

二、详细说明

2.1 axios 是什么 / 基本用法

  • 发请求的库：axios.get(url, config) / axios.post(url, data, config) / axios.request({ method, url, data, ... })
  • 所有请求最终都走同一个入口：axios.request(config)，即 get/post/put/delete 只是 request 的语法糖
  • 核心概念三件套：
    • config：请求配置（url/method/headers/data/params/timeout/withCredentials/validateStatus/adapter…）
    • AxiosResponse：响应对象（{ data, status, statusText, headers, config, request }）
    • AxiosError：错误对象（{ message, code, config, request, response }，code 有 ERR_NETWORK/ECONNABORTED/ERR_BAD_REQUEST/ERR_BAD_RESPONSE/ERR_CANCELED 等）

2.3 一次请求的内部流程（7 步）

2.4 请求拦截器：出门前的”加工”（http.ts:61-71）

要点：

  • 拦截器不拦截请求，只修改 config（加 header 等），改完必须 return config
  • 多个拦截器按注册顺序执行；可在拦截器里 return Promise.reject 主动中断请求
  • 本项目 3 个动作：请求ID（链路追踪）、Bearer Token（联调认证）、CSRF（写操作防跨站）

2.5 adapter：可插拔的”发送器”（核心机制）

  • axios 把”真正把请求发出去”这一步抽象成 adapter，签名：(config) => Promise<AxiosResponse>
  • 默认 adapter 内部用浏览器 XHR（或 Node http）发起网络请求
  • 替换方式：http.defaults.adapter = mockAdapter（installMockAdapter，http.ts:58）
  • 为什么能拦截：adapter 被换后，axios 到发送这一步根本不碰网络，直接在函数内部把请求处理完返回 AxiosResponse——对 axios 上层（拦截器、业务代码）来说，看起来”请求成功发出并收到响应了”

本项目 mockAdapter（client.ts:67-105）内部 4 个小工具：

方法 行号 作用
resolveUrl(config) client.ts:8 baseURL + url + params 拼完整 URL（含 query）
requestBody(config) client.ts:23 GET 无 body；POST/PUT 把对象 JSON 序列化
requestHeaders(config) client.ts:38 axios headers → 标准 Headers
parseResponseBody(response, responseType) client.ts:54 Response → data（arraybuffer/blob/text/json）

2.6 响应拦截器：回来后的”收尾”（http.ts:73-122）

失败分支处理 3 件事：

  1. GET 暂时性失败重试：ERR_NETWORK/ECONNABORTED/ETIMEDOUT 且无 response、非用户取消 → 按 [300, 900] 毫秒延迟重试（最多 2 次）。只重试 GET（读操作安全），不重试写请求（防重复业务数据）；mock 模式 maxRetryCount = 0 不重试
  2. 401 触发未登录处理：unauthorizedHandler?.(error) → main.ts 里注册的回调：auth.handleUnauthorized() 清状态 + 跳登录页（带 reason=expired 和 redirect）
  3. 统一包装成 ApiError：业务代码只需要 catch (e) { e instanceof ApiError } 一种处理方式

2.7 错误体系：AxiosError → ApiError

  • axios 抛 AxiosError（网络层/HTTP 状态码层），字段含 code/response.status 等
  • 响应拦截器把它转成项目统一的 ApiError（http.ts:114-120）：
    • message：优先用后端返回的 body.message，否则用本地 fallback（mock 下是”本地演示数据处理失败，请刷新页面后重试”）
    • code：body.code 或 AxiosError.code 或 'NETWORK_ERROR'
    • requestId：兼容后端 traceId
    • fieldErrors：兼容后端顶层 errors: { field: string[] } 与前端 data.errors: FieldError[]
  • 所以页面里统一 catch (error) { ElMessage.error(error.message) } 即可

2.8 unwrap：剥出业务数据（http.ts:124-144）

  • 后端响应统一格式：{ success, code, message, data, requestId }（mock 的 ok()/fail() 就是按这个契约造的）
  • unwrap 负责：校验 success → 剥出 data → 分页字段兼容 → 失败抛 ApiError

2.9 关键配置一览（http.ts）

配置/机制 值/行为 用途
baseURL runtimeConfig.apiBaseUrl 联调后端地址；mock 模式下实际不用（请求被 adapter 截断）
timeout mock: 0 / 真实: 15s 防休眠计时器误报
withCredentials true 携带 Cookie
请求拦截器 X-Request-Id + Authorization + CSRF 认证与追踪
adapter mock: mockAdapter / 真实: XHR Mock 的截断点
响应拦截器 GET 重试、401 跳转、ApiError 包装 统一错误体验
Vite proxy /api → http://localhost:5000（vite.config.ts:37） 联调转发到 .NET 后端

四、踩坑记录

  • 坑：请求拦截器里改完 config 忘记 return config → 原因：拦截器函数返回值会传给下一环节，不返回则链条中断 → 解决：永远记得 return config
  • 坑：mock 模式下 DevTools Network 面板看不到 /api 请求 → 原因：adapter 被替换，请求没经过浏览器网络 → 解决：属正常现象；这就是 mock 生效的证明
  • 坑：GET 请求偶尔被自动重发 → 原因：休眠唤醒触发 ERR_NETWORK，响应拦截器按 [300,900]ms 重试 → 解决：属防御设计；若不想重试可去掉 isTransientFailure 判断
  • 坑：401 后页面”半退出”（只剩导航没内容） → 原因：只清了状态没跳路由 → 解决：main.ts 里 setUnauthorizedHandler 已处理：router.replace({ name:'login', query:{ reason:'expired', redirect } })，且加了 redirectingAfterUnauthorized 防重入
  • 坑：后端错误信息没显示，显示的是”网络请求失败” → 原因：fallbackMessage 兜底；后端没返回 message 字段 → 解决：检查后端响应是否带 { success:false, message, code }
  • 坑：分页显示”没有 totalPages 字段”类型报错 → 原因：真实后端分页只返回 items/page/pageSize/total → 解决：unwrap() 已自动补 totalPages = ceil(total/pageSize)

六、记忆口诀

  • 拦截器管加工，adapter 管拐弯：请求拦截器加头、响应拦截器收尾、adapter 决定请求走不走网络
  • 一条请求七步走：调用 → 合并配置 → 请求拦截器 → adapter(发送/被Mock截断) → AxiosResponse → 响应拦截器 → 业务代码
  • 失败统一 ApiError：网络错、超时错、业务错，页面只 catch 一种
  • unwrap 剥 data：{success,data} 契约 → 组件拿到的永远是纯业务数据
  • 切 Mock 只改一处：http.defaults.adapter，业务代码零改动
